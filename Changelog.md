# Release History



### 1.0.0 ( 2026-08-01 )
- [x] **New API — `range.select()`**: returns a deep clone of the range contents as a `DocumentFragment`. The fragment is detached from the live DOM and safe to mutate — pair it with `update(fragment)` for a round-trip (read → mutate → write back). Solves the "multiple sibling regions under a common parent" case without relying on `window.getSelection()`. Returns `null` when the range is orphaned;
- [x] **New API — `range.extract(keepCache?)`**: like `delete()` but returns the removed content as a `DocumentFragment` first, so the caller can re-insert it elsewhere. Pass `'cache'` to keep the snapshot in the undo stack so `back()` can restore it. Returns `null` when orphaned;
- [x] **New API — `range.isOrphan()`**: silent orphan check — `true` if either marker has been detached from the DOM. Distinct from `isEmpty()` / `getContext()` in that it does *not* log a `console.warn`, so it's safe inside UI loops;
- [x] **New API — `range.toString()`**: plain-text content of the range (empty string when orphaned);
- [x] **`update()` / `prepend()` / `append()` accept `Node | string`**: previously these only accepted an HTML string. Now they also accept a `DocumentFragment`, `Element`, or any other `Node` — round-trips cleanly with `select()`. The string form is unchanged and still parsed as HTML;
- [x] **`reset(names?)` is selective**: no argument behaves as before but now ALSO removes every marker still attached to the DOM (previously `reset()` only cleared the registry and left markers in the tree — closed this asymmetry). With an alias, numeric index, array, or comma-separated string, `reset()` removes just those ranges' markers and registry entries;
- [x] **New API — `d.list()`**: returns every registry key — aliases first (registration order), then numeric indexes (registration order), deduplicated. Useful for bulk operations ("iterate every region, save state, render all slots") that reach ranges the caller never aliased;
- [x] **New API — `d.aliases()`**: returns only the user-named aliases, in registration order;
- [x] **New API — `d.has(name)`**: `true` if every requested range exists. Accepts a single key, an array, or a comma-separated string. Cheap existence check that mirrors `get()`'s input shapes;
- [x] **Numeric IDs everywhere**: `get(0)`, `has(0)`, `reset(0)`, `get(['a', 0])` all work — non-negative integers are coerced to their string form via a single `coerceName()` helper. Updates the BUG 2 regression test (which previously pinned `get(0)` as `undefined`) and adds two new tests (numeric lookup; mixed-type array);
- [x] **Internal: `range.destroy()`**: private hook called by `reset()` to detach the start and end markers from the DOM if still connected. Attached via `Object.defineProperty` with `enumerable: false` so it does not appear in `Object.keys(range)`, `JSON.stringify(range)`, or any other iteration of the range object. Not exposed on the public `RangeApi` typedef; 1 regression test pins it as non-enumerable;
- [x] **Fix: UMD `window.dim` was a namespace object `{ default: [Function] }`, not the function** — so the documented browser snippet `const d = dim()` threw `TypeError: dim is not a function`. The CJS bundle had the symmetric issue (`require('@peter.naydenov/dim')` returned `{ default: [Function] }`, forcing destructuring). Both fixed by removing the redundant `rollupOptions.output.exports: 'named'` setting from `vite.config.js` (the source uses only `export default dim`, so Rollup can infer the right shape). Now `module.exports = dim` (CJS) and `window.dim = dim` (UMD) — `dim` is the function directly across all three module systems. The README's CJS example needed updating (`const dim = require(...)` instead of `const { default: dim } = require(...)`) — noted in the changelog as a breaking change for 0.1.x consumers;
- [x] **Fix: `reset(null)` / `reset({})` / `reset(true)`** were throwing `TypeError: name.split is not a function`. `get()` and `has()` already had type guards; with the new selective `reset(names?)` the input shape had grown but the guard had not. `reset()` now mirrors `get()`/`has()` — bad input is a silent no-op, `reset()` and `reset(undefined)` still clear everything. 1 regression test;
- [x] **Fix: `update(null)` / `update(undefined)` / `update(0)` etc. silently destroyed the range content THEN threw an opaque browser `TypeError: Failed to execute 'insertNode' on 'Range': parameter 1 is not of type 'Node'`** — the worst of both worlds (data loss + confusing error). `prepend` / `append` had the same problem but only wasted a cache snapshot since they don't delete content. All three now validate `code` BEFORE any mutation via a new `_validateContentInput()` helper: if `code` is not a string and not a `Node`, throws `TypeError: update/prepend/append require a string or a Node; received <type>` and existing content + cache are untouched. 3 regression tests (one per method), each asserting both the throw AND content preservation across `[null, undefined, 0, false, {}, [], true]`;
- [x] **Internal: `coerceName()` / `toList()` / `dedupe()`** module-level helpers behind `get` / `has` / `reset` — single source of truth for normalising registry keys;
- [x] Docs: README updated — new "Read → mutate → write back" section showing the `select()` → mutate → `update(fragment)` round-trip; `get`/`update`/`prepend`/`append`/`reset` signatures and tables updated; orphan-detection section now lists `select`, `extract`, `toString`, `isOrphan` behaviour;
- [x] **Docs fix**: `prepend()` and `append()` were documented as inserting *outside* the markers ("before the start marker" / "after the end marker"). They actually insert *inside* the range, at the start (`start.after`) or end (`end.before`). Fixed the README, the `RangeApi` typedef, the per-method JSDoc, and the test descriptions in `test/01-general.test.js`. Added two new tests that explicitly assert position: `prepend` after `update('<span>middle</span>')` yields `<b>head</b><span>middle</span>` (prepended content first, existing content second); `append` yields `<span>middle</span><i>tail</i>` (existing content first, appended content second);
- [x] **Docs fix**: README's "Look up ranges" example had a typo `d.get(['x', y])` that referenced an undefined variable `y` and would throw at runtime. Changed to `d.get(['x', 'y'])`;
- [x] **Docs fix**: README's Range API table now mentions that `update` / `prepend` / `append` throw `TypeError` on bad input (`null`, `undefined`, number, boolean, object) BEFORE any mutation — previously the "string or Node" hint wasn't sufficient to communicate the throw contract;
- [x] Tests: 39 → 79 passing (38 new tests covering `select` (6), `extract` (4 — added cross-region move), `update/prepend/append` accepting `Node` (3), `update/prepend/append` input validation (3 — new TypeError guard), selective `reset` (7 — added bad-input no-op and `destroy` non-enumerable), `list` / `aliases` (3), `has` (4), `isOrphan` (3), `toString` (3), numeric-id coverage for `get` (2), plus 2 position tests that pin `prepend`/`append` to the INSIDE of the range);
- [x] **Shipped AI-agent skill at `.agents/skills/peter-naydenov-dim/`** (`SKILL.md` + `references/api.md` + `references/pitfalls.md`), bundled in the published tarball so any agent consuming `@peter.naydenov/dim` can read the v1.0.0 contract from `node_modules/@peter.naydenov/dim/.agents/skills/peter-naydenov-dim/` and install it into its own skills dir on demand. Most agents auto-pick-up project skills from `.agents/skills/` on cold start inside this repo (no install needed). To sync the skill into a local agent's skills dir for use in *other* projects, `npm run sync-skill` (copies `.agents/skills/peter-naydenov-dim/` into `~/.minimax/agents/mavis/skills/peter-naydenov-dim/`, overridable with `--agent <name>` or `MAVIS_AGENT_NAME`). Pure Node.js, no deps, cross-platform, idempotent;



### 0.1.4 ( 2026-07-28 )
- [x] Fix: `prepend` and `append` did not refresh the range before snapshotting the cache. After a prior `update` (or any `insertNode`) the underlying `Range` is collapsed at "after the inserted content" per the DOM Range spec, so `range.cloneContents()` returned an empty `DocumentFragment` — the cache held nothing, and a subsequent `back()` deleted the range content without restoring it (silent data loss). Added `refreshRange()` before the cache snapshot in both methods. 2 regression tests (one for `append`, one for `prepend`) — `update('<x>'); range.append('<y>', 'cache'); range.back()` now correctly restores `'<x>'`;
- [x] Fix: `set()` threw the opaque DOMException `InvalidNodeTypeError: The given Node has no parent.` (raised by `range.setStartAfter` per spec) when the callback forgot to attach the `start` and/or `end` markers. Now `set()` validates immediately after the callback returns and throws a clear `Error: dim.set: callback must attach both "start" and "end" markers to the DOM` — no DOMException, no need to know the Range spec to diagnose. 1 regression test covering all three failure shapes (nothing attached, only `start` attached, only `end` attached);
- [x] Fix: README's CommonJS import example was broken — `const dim = require('@peter.naydenov/dim')` returned the module namespace object (`{ default: [Function] }`), not the function itself. The CJS bundle is built as a default-export-only ESM-as-CJS module. Updated the snippet to `const { default: dim } = require('@peter.naydenov/dim')` (with `.default` shown as an alternative);
- [x] Docs: README's "Orphan detection" section claimed "Every Range API method guards against this", but `clearCache` does not run `validate()` — it only mutates the internal cache array, which is harmless on an orphaned range. Listed `clearCache` in the no-op table to match reality instead of overclaiming;
- [x] Docs: added a UMD import example (`<script src=".../dim.umd.cjs">` exposes `window.dim`) since `package.json` exposes `"./umd"` but the README didn't mention it;
- [x] Docs: reworded "parsed as HTML and inserted **live** into the DOM" → "parsed as HTML and inserted into the DOM" (the "live" was unusual phrasing);
- [x] Tests: 36 → 39 passing;
- [x] Cleanup: fixed "Apply start and end **makers**" → "markers" comment in `src/main.js`, and "**Mmultiple** ranges" → "Multiple" test name in `test/01-general.test.js`;

### 0.1.1 ( 2026-07-23 )
- [x] Fix: range API operations were silently shrinking the effective range over time. The `makeMyAPI` range object was created once in `set()` and reused across every operation without ever being reset. Per the DOM Range spec, `insertNode` moves the range's end position to *after* the inserted content and `deleteContents` collapses the range — so after the first `update`/`delete`/`back`, the range no longer covered `[after start, before end]`, and each subsequent operation worked on a smaller and smaller area. The orphan-detection feature (`validate()` checking `start.isConnected`) could never fire because the drift meant child markers placed *between* the start and end were never actually deleted by `range.deleteContents()`. Added a `refreshRange()` helper that re-anchors the range via `setStartAfter` / `setEndBefore` before every modifying operation (`update`, `delete`, `back`, `isEmpty` — `prepend`/`append` use `start.after` / `end.before` and don't need it). Confirmed via probe: with child markers placed between parent markers, `parentRange.update('')` now correctly removes them and `validate()` logs the warning. Previously the child markers were silently still in the DOM after the parent's update;
- [x] Fix: `get()` crashed with `Cannot read properties of undefined (reading 'includes')` (or `name.includes is not a function`) on `undefined` / `null` / non-string / number / object input — the JSDoc says `string|string[]` but a user passing the wrong type got a raw JS error instead of a clean `undefined`. Added a type guard that returns `undefined` for any non-string non-array argument, so the call is harmless instead of crashing the consumer;
- [x] Fix: `set()` threw the generic `fn is not a function` when called with anything other than a function as the first argument. Now throws a clear `TypeError: set() requires a function as the first argument` before any work is done (no TextNodes created, no partial state);
- [x] Tests: 3 BUG 1 regression cases (orphan works after the parent's update, repeated updates don't shrink the effective range, `isEmpty()` reports the live state), 2 BUG 2 regression cases (invalid input returns `undefined`, empty array returns `[]`), 1 BUG 3 regression case (TypeError with a clear message). 30 → 36 passing tests;
- [x] Tests: rewrote the existing "isEmpty() should return true when child range is orphaned" — the original setup appended child markers to the parent container *after* `parentEnd`, so they were never inside the parent's range, and the "orphan" check never fired. The rewritten setup places child markers *between* `parentStart` and `parentEnd` so the parent's `update('')` actually deletes them, and the test now exercises the real orphan path (the `console.warn` warning inside `validate()` is what was previously uncovered);
- [x] Docs: README rewrite;
