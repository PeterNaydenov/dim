# AGENTS.md

`@peter.naydenov/dim` — invisible DOM markers for editable ranges. A single-file
library (`src/main.js`, ~700 lines) shipped as ESM / CJS / UMD. ESM by default,
JSDoc-typed, types generated by `tsc`.

## Setup commands

- Install:     `npm install`
- Build:       `npm run build`           (`build:js` first — empties `dist/` — then `build:types`)
- Test:        `npm test`                (vitest single run, jsdom environment)
- Test watch:  `npm run test:watch`      (vitest watch mode)
- Coverage:    `npm run cover`           (writes to `coverage/`)
- Typecheck:   `npm run typecheck`       (tsc over `src/**/*.js` with `checkJs: true`)
- Pre-publish: `npm run prepublishOnly`  (typecheck + tests + build — do not skip)

## Project layout

- `src/main.js` — the entire library. JSDoc-typed; `dist/main.d.ts` is generated from it.
- `test/01-general.test.js` — vitest suite (single file, jsdom). Add new behaviour here.
- `dist/` — generated artifacts. Never edit by hand. `main.d.ts` (ESM) and `main.d.cts`
  (CJS, derived by `scripts/make-cts.js` during `build:types`) are the published types entries.
- `index.html` — self-contained counter demo. `vite` serves it via `npm run dev`.
- `Changelog.md` — reverse-chronological release history. New release → add a block at the top.

## Code style

- JSDoc on every public function and typedef. `tsc` reads the JSDoc to produce
  `dist/main.d.ts`; `checkJs: true` + `noEmitOnError: true` mean a missing or
  wrong JSDoc type is a build failure, not a silent bug.
- ESM, `target: ES2020`, no runtime dependencies, one default export (`dim`).
- No ESLint / Prettier configured. Match the existing tab-indent, single-quote,
  trailing-comma style; see `src/main.js` and `test/01-general.test.js`.
- Test naming: `it ( 'should ...' )` inside `describe ( 'Range API - <method>()' )`
  blocks. Add new `describe` blocks in the existing alphabetical position.

## Testing instructions

- Framework: vitest + jsdom (`vitest.config.js`). `beforeEach` resets `document.body`.
- Pattern: build a host, call `d.set(({ start, end }) => { ... })`, assert on
  the host's `innerHTML` or on a fragment from `range.select()`.
- New behaviour MUST come with a regression test. Add a `describe` block in
  `test/01-general.test.js` in the matching position; do not create new test files.
- All tests must pass before opening a PR. CI runs `npm test` on Node 18+.

## PR & commit conventions

- Branch from `main`; never push to it directly.
- Commit message: short imperative summary (no conventional-commits prefix —
  see `git log --oneline`).
- **Do not bump `package.json` "version" or write release dates in
  `Changelog.md`** — the maintainer controls both. If a new release record is
  needed, write the header as `### <next-version> (unreleased)` and leave the
  version + date for the maintainer to fill in.
- Run `npm run prepublishOnly` locally before requesting a release.

## Security

- `engines.node`: `>=18`. Do not depend on Node 16-only APIs.
- The library parses HTML strings via `<template>.innerHTML` and inserts the
  result into the live DOM. Untrusted / user-supplied input must be sanitized
  at the call site — the library does not escape.

## Project-specific AI skill

A skill is shipped with the package so any agent working with the dim
public API has the v1.0.0 contract at hand.

- **Source of truth (this repo):** `.agents/skills/peter-naydenov-dim/`
  (`SKILL.md` + `references/api.md` + `references/pitfalls.md`).
- **When working in this repo:** most agents auto-pick-up project skills
  from `.agents/skills/` on cold start — no install needed.
- **When installed via npm:** the skill is also bundled in the published
  tarball at `node_modules/@peter.naydenov/dim/.agents/skills/peter-naydenov-dim/`.
  The package declares it in `package.json#agents.skills` so any agent
  runtime that reads that field can offer to install the skill into its
  own skills directory on demand. The agent decides where the skill
  belongs on its own machine — the package only describes the skill
  and where to find it in the tarball.
- **For downstream developers:** no per-project setup is needed. Once
  they `npm install @peter.naydenov/dim`, their agent (if it reads
  `package.json#agents.skills`) will discover the skill and can copy
  it into the appropriate skills dir. No personal sync scripts, no
  per-developer config.

What the skill encodes (load it when any of these apply):

- Adding a `RangeApi` method or changing the public contract.
- Debugging orphan ranges, range drift across `update` calls, or `'cache'`
  / `back()` semantics.
- Writing a regression test for a Range method (the project's vitest +
  jsdom test pattern is the same as the skill describes).
- Answering a user question about how to use `dim` in their own app.
- The `'cache'` argument is a string, not a boolean — easy to get wrong.
- XSS handling: `update` parses HTML strings live; the Node form
  (`createElement` + `textContent`) bypasses the parser and is the
  recommended path for untrusted input.
- **Do not confuse with `@peter.naydenov/morph`** (DOM diffing / template
  engine with `create` / `html\`\`` / `mount` API) — that is a different
  library by the same author with a different API.
